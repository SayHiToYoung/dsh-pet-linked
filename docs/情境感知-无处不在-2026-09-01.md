# 桌宠「陪伴无处不在 + 情境感知」方向与开发计划

> 定稿 2026-09-01。本文是下一阶段开发的唯一权威输入：先定方向，再动代码。
> 一句话：**桌宠是唯一的产品，其他全是它的舞台。** 办公区（dsh-agent-office）从「主菜」降级为「舞台之一」。

---

## 0. 方向结论（别在开发中途再回头纠结）

1. **主线 = 陪伴无处不在**，不是「多智能体可视化」。专业化数据（8 态、token、子代理树）全部**藏进背景**，可爱与陪伴**浮出来当主角**。
2. **卖点 = 桌面端常驻 + DSH 联动**：不工作时桌宠也常驻桌面陪着；工作时它同步感知你在干嘛。两者叠加才是别人抄不走的点。
3. **核心新能力 = 情境感知**：监听前台应用/进程，知道「现在该不该打扰」，而不是「读你看了什么」。

---

## 1. 情境感知（本期核心开发项）

### 1.1 产品语义

桌宠**不读用户内容，只感知前台情境**——这是与「读微信聊天」的根本区别，也是隐私红线的落点：

- 读微信内容 = 走不通 / 擦边 / 封号风险 → **明确不做**。
- 监听前台应用 = 本地、合法、稳定、无特殊权限 → **本期做这个**。

### 1.2 情境状态机（第一版）

| 情境 | 触发（前台 App） | 桌宠行为 | 打扰级别 |
|---|---|---|---|
| 🎮 游戏 | Steam / 游戏客户端在前台 | 缩到角落打盹、静音、不弹气泡 | 免打扰 |
| 📹 开会 | 腾讯会议 / 钉钉 / Zoom 在前台 | 淡出成小气泡/收进托盘，散会再回来 | 隐身 |
| 💼 工作 | DSH / IDE 在前台 | 精神起来，跑工位/报状态，陪伴干活 | 陪伴 |
| 🧘 专注 | 用户手动「别打扰」 | 隐身/待机 | 免打扰 |
| 🐳 空闲 | 桌面空着 | 常驻卖萌、到处游 | 正常 |

### 1.3 技术要点

- **监听「前台应用」优先于「新进程」**：进程在后台挂着 ≠ 用户正在用。
  - macOS：`NSWorkspaceDidActivateApplicationNotification`（切到哪个 App 立刻知道，无需 Screen Recording）。
  - Windows：`GetForegroundWindow` + `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`。
- **优先级（冲突时定死）**：会议 > 游戏 > 工作 > 空闲。
- **防抖 2~3 秒**：Alt-Tab 快速切换不得让桌宠闪进闪出。
- **「躲起来」= 淡出/收托盘，不是杀进程**。散会再飘回来，才有「懂事」的感觉。

### 1.4 用户可控

- 设置界面新增「情境感知」页：App 白名单/黑名单（用户可加可删）、各情境阈值（分钟）、
  「现在别打扰我」手动开关。
- 全部存 `config.json`（新键，跨重启保留），沿用现有 `modern_settings_dialog` 的信息架构。

## 2. Connector 架构（落地「无处不在」）

核心引擎只吃**事件流**，每个平台/能力做成一个可插拔 `connector`：

```
核心引擎：只消费事件流 {event, context, app, ts}
  ├─ connector: DSH 工作状态（现有 work_state / 信标）
  ├─ connector: Token 账本（现有 session_reader）
  ├─ connector: 办公区镜像（现有 office_link / 47890）
  ├─ connector: 情绪响应（现有 emotion_actor）
  └─ connector: 情境感知（本期新增，前台应用监听）
```

原则：

1. **够得着的全接上，够不着的（微信个人版内容）不做**，红线不碰。
2. 各 connector 只产出统一事件，动画/行为决策由核心引擎统一裁决，避免多套工作态打架。
   已实现的裁决优先级（P3 定稿）：

   ```
   情境感知（meeting/focus 躲起、gaming 安静）   ← 最高，压过一切
     > 办公区 office 镜像（7 秒心跳内）
       > DOM 信标 work_state（兜底）
   ```

   落地：`pet/context_aware.context_blocks_interrupt()` 是统一裁决的纯函数；
   `PetWindow.is_quiet()` / `mirror_agent()` / `set_work_state()` 都从它派生，
   保证「开会/专注/游戏」时任何来源（office 镜像、审批召唤、气泡）都不打扰。

## 3. 开发阶段

| 阶段 | 内容 | 交付 |
|---|---|---|
| P0 | 情境感知 connector：前台应用监听 → 产出 `context` 事件 | `pet/context_aware.py` + 单测 |
| P1 | 情境状态机接入现有行为系统（`set_work_state` / 动画池 / 气泡） | 桌宠按情境切换行为 |
| P2 | 设置界面「情境感知」页 + 白名单/黑名单 + 手动开关 | `modern_settings_dialog` 扩展 |
| P3 | 与办公区统一事件流（把 office 定位降为舞台，不影响现有联动） | 文档 + 回归测试 |

> P0 做完即可进入开发联调；P1/P2 是体验闭环；P3 是收尾。

## 4. 一句话卖点（对外口径）

> **一只常驻桌面的 AI 桌宠：你不工作时它陪着你，你工作（DSH）时它同步感知你在做什么；
> 打游戏不打扰、开会自动隐身，用最小权限实现最大的「懂事」。**
